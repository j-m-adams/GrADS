## Introduction to GrADS scripts

Scripts let you program GrADS operations. Although sophisticated graphics can
often be produced interactively, scripts are useful for repeatable workflows,
animation, point-and-click interfaces, and annotations based on query output.

### What scripts can do

The scripting language is invoked with the GrADS [`run`](gradcomdrun.md)
command. It is similar to [`exec`](gradcomdexec.md), but adds flow control,
variables, functions, and access to the output of GrADS commands. Scripts can
also issue strings generated by expressions as GrADS commands.

The implementation is similar to REXX. All variables contain strings, although
numeric operators are available when their operands represent numbers. Flow
control uses `if`/`else`/`endif` and `while`/`endwhile`; `continue` and `break`
can change loop execution. Text returned by a GrADS command is placed in the
`result` variable and its integer return code is placed in `rc`.

Before writing a script, try examples from the [script library](library.md),
using this page as a syntax reference.

### Running scripts

Use the [`run`](gradcomdrun.md) command to execute a script:

```text
run filename [arguments]
```

The file normally has a `.gs` suffix. Optional `arguments` are passed to the
script as one string. A script may issue any GrADS command, including `run`;
when scripts call one another recursively, make sure the recursion can return
to the calling script.

### Automatic script execution

The [`set imprun`](gradcomdsetimprun.md) command runs a script before every
[`display`](gradcomddisplay.md) command:

```text
set imprun script-name
```

This is useful for options that are reset by `display`, for example:

```text
set grads off
```

The automatic script receives the expression from the `display` command as its
argument. It may issue any GrADS command, but issuing another `display` from
the automatic script can create infinite recursion.

(storing)=
## Storing GrADS scripts

It is convenient to keep utility scripts in one directory. GrADS searches for
a script in this order:

1. The current directory, using the name exactly as supplied.
2. The current directory with `.gs` appended.
3. Each directory in `GASCRP`, with and without `.gs` as needed.
4. `GADDIR`, which makes packaged scripts such as `nebasemap.gs` available.

Thus a file named `t.gs` can be run as:

```text
run t
```

For a custom script library, set `GASCRP` in the shell before starting GrADS.
For example:

```text
# csh/tcsh
setenv GASCRP /home1/grads/lib

# sh/bash/ksh
export GASCRP=/home1/grads/lib
```

A trailing slash is optional. The following two commands are equivalent:

```text
display slp
run /home1/grads/lib/cbarn.gs
```

and:

```text
display slp
run cbarn
```

(elements)=
## Elements of the language

A script consists of records. A record ends at a newline or at a semicolon
that is outside a quoted string. Records can be:

| Record type | Purpose |
| --- | --- |
| Comment | Documentation, introduced by `*` in column one |
| Statement | Evaluate an expression and submit the result to GrADS |
| Assignment | Store an expression result in a variable |
| `say`, `prompt`, `pull` | Read or write terminal text |
| `if`, `else`, `endif` | Conditional execution |
| `while`, `endwhile`, `break`, `continue` | Loop execution |
| Function header, `return` | Define and leave a script function |

Expressions contain operands (string constants, variables, or function calls)
and operators. The following sections describe each record type.

(comment)=
### Comments

A comment has an asterisk (`*`) in the first column:

```text
* this is a comment
```

(statement)=
### Statements

A statement consists of one expression. The expression is evaluated and the
resulting string is submitted to GrADS as a command:

```text
expression
```

The `rc` variable receives the integer return code. Any text written by GrADS
in response to the command is placed in `result`. An invalid GrADS command
does not by itself terminate the script.

For example:

```text
* a simple script
'open my_sst_dataset.ctl'
'set lat -30 30'
'set lon 90 300'
'display sst'
```

(assignment)=
### Assignments

An assignment evaluates an expression and stores the result:

```text
variable = expression
```

The following example uses both explicit (`%`) and implied concatenation:

```text
'open my_sst_dataset.ctl'
minlat = -30
maxlat = minlat + 60
minlon = 90
maxlon = 300
'set lat 'minlat%' '%maxlat
'set lon 'minlon' 'maxlon
'display sst'
```

(standardio)=
### `say`, `prompt`, and `pull`

Use `say` and `prompt` to write to the terminal:

```text
say expression
prompt expression
```

Both evaluate `expression`; `prompt` does not append a newline. Variables and
string constants can be combined:

```text
line = "Peter Pan, the flying one"
say line
say 'She said it is 'line
```

This prints:

```text
Peter Pan, the flying one
She said it is Peter Pan, the flying one
```

Use `pull` to read one line from standard input and assign it to a variable:

```text
pull variable
```

For example:

```text
'open my_sst_dataset.ctl'
prompt 'Enter min and max latitudes: '
pull minlat maxlat
prompt 'Enter min and max longitudes: '
pull minlon maxlon
'set lat 'minlat%' '%maxlat
'set lon 'minlon' 'maxlon
'display sst'
```

(ifendif)=
### `if` / `else` / `endif`

The conditional form is:

```text
if expression
  script record
  script record
else
  script record
endif
```

The `else` block is optional, but `endif` is required. The `if` block runs
when the expression contains the character `1`; an expression containing `0`
selects the `else` block, if present. The `if` record and its body must be
separate records. This is invalid:

```text
if (i = 10) j = 20
```

Write it as three records, or separate the records with semicolons:

```text
if (i = 10)
  j = 20
endif
```

```text
if (i = 10) ; j = 20 ; endif
```

There is no `elseif` construct. Nest another `if` when more than two branches
are required.

(while)=
### `while` / `endwhile`

The loop form is:

```text
while expression
  script record
  script record
endwhile
```

The body runs while the expression evaluates to `1`. `break` exits the loop
and continues after `endwhile`; `continue` jumps to the top of the loop and
re-evaluates the expression.

A counter loop can be written as follows:

```text
count = 1
while (count < 10)
  'set t 'count
  'display z'
  if (rc != 0) ; break ; endif
  count = count + 1
endwhile
```

(variables)=
### Variables

Variables always contain character strings. If a value is numeric, operators
that support numbers can produce a numeric result, which is stored as a
string. Names are case-sensitive, begin with a letter, and contain letters or
numbers. An unassigned variable has its own name as its value.

String values may use single or double quotes:

```text
name = 'Peter Pan'
name = "Peter Pan"
number = -99.99
```

Numeric values such as `-99.99` are still strings internally.

#### Predefined variables

The following variables are maintained by GrADS and change after commands:

| Variable | Contents |
| --- | --- |
| `rc` | Integer return code from the most recent GrADS command |
| `result` | Text output from the most recent GrADS command |

`lat`, `lon`, and `lev` are also used internally by GrADS. They can be used in
a script, but avoiding those names reduces confusion.

#### Global string variables

Variables are normally local to the function in which they are used. A name
beginning with an underscore (`_`) is global and retains its value throughout
the script file:

```text
_var1 = "global variable 1"
```

Global variables cannot be used in function headers. For example,
`function dostuff(_var)` is invalid because `_var` is already global.

#### Compound string variables

Compound variables provide array-like names with period-separated segments:

```text
varname.i.j
```

Each segment is substituted if it names another (non-compound) variable:

```text
i = 10
j = 3
varname.i.j = 343
```

This creates `varname.10.3` with value `343`. A substituted segment can contain
any string, but the name written in the script must follow the normal naming
rules. Variable names may not exceed 16 characters before or after
substitution.

Compound variables are inefficient for very large arrays. For example, the
following loop creates 10,000 variable names and can substantially slow a
script:

```text
i = 1
while (i < 10000)
  var.i = i
  i = i + 1
endwhile
```

(operators)=
### Operators

| Operator | Meaning |
| --- | --- |
| `\|` | Logical OR |
| `&` | Logical AND |
| `!` | Unary NOT |
| `-` | Unary minus or subtraction |
| `=` | Equal |
| `!=` | Not equal |
| `>` | Greater than |
| `>=` | Greater than or equal |
| `<` | Less than |
| `<=` | Less than or equal |
| `%` | Concatenation |
| `+` | Addition |
| `*` | Multiplication |
| `/` | Division |

The comparison operators and `+`, `-`, `*`, and `/` use numeric operations
when both operands are numeric. Arithmetic with nonnumeric operands produces
an error. Arithmetic is performed in floating point; integral results are
rendered without a decimal point. Logical results are the strings `0` (false)
and `1` (true).

(expressions)=
### Expressions

Expressions may combine constants, variables, function calls, operators, and
parentheses. Operator precedence, from highest to lowest, is:

| Level | Operators |
| ---: | --- |
| 1 | Unary `-`, `!` |
| 2 | `/`, `*` |
| 3 | `+`, `-` |
| 4 | `%` |
| 5 | `=`, `!=`, `>`, `>=`, `<`, `<=` |
| 6 | `&` |
| 7 | `\|` |

Operations at one level are evaluated from left to right. Parentheses can
override this order. The expression result is the string submitted when the
expression is used as a statement:

```text
var1 = -1
var2 = 10
if (var1 * var2 < 10 & var1 > 0)
  say 'both statements are true'
else
  say 'it is not the case that both statements are true'
endif
```

Both sides of the logical operation are evaluated. Here the first comparison
is true, the second is false, and the complete expression is `0`.

#### Concatenation

The `%` concatenation operator may be omitted when one operand is a string
constant and the other is a variable. With implied concatenation, intervening
blanks are ignored. These expressions are equivalent:

```text
'set lat 'minlat%' '%maxlat
'set lat 'minlat' 'maxlat
```

With `minlat = -30` and `maxlat = 30`, both produce:

```text
set lat -30 30
```

Keep precedence in mind when combining concatenation with arithmetic or
logical operators.

(functions)=
### Functions

A function call has the form:

```text
name(arg, arg, ...)
```

The name follows the variable naming rules and each argument can be any
expression. A function returns one string and may accept zero or more string
arguments. Parentheses are required even when there are no arguments:

```text
name()
```

Define a function in the current script with:

```text
function name(variable, variable, ...)
```

Return a value with:

```text
return expression
```

The expression is optional; omitting it returns the NULL string (`''`).
Arguments are evaluated before control enters the function and initialize the
parameters in its function header. Missing trailing arguments are
uninitialized; extra arguments are discarded. Changing a parameter does not
change the variable in the calling routine.

Variables are normally local to a function, except for names beginning with
`_`, which are global. Other script files cannot currently provide callable
functions; they can be executed with `run`.

When a script is first invoked with `run`, execution starts at the beginning.
The file may optionally start with a function definition containing one
parameter. That parameter receives the `run` options, or NULL when no options
were supplied.

(intrinsic)=
### Intrinsic functions

#### `strlen(string)`

Returns the number of characters in `string`.

#### `sublin(string, n)`

Returns line `n` from a multi-line string. If there are too few lines, it
returns NULL. `n` must be an integer.

#### `subwrd(string, n)`

Returns word `n` from a string, or NULL when the string has too few words. `n`
must be an integer.

#### `substr(string, start, length)`

Returns the substring beginning at `start` for `length` characters. If the
source is shorter, the result is shortened or NULL. Both arguments must be
integers.

#### `read(filename)`

Reads one record from `filename`. Repeated calls read consecutive records. The
result contains two lines: a return code followed by the record (maximum 80
characters). Use `sublin` to separate them.

| Code | Meaning |
| ---: | --- |
| 0 | Success |
| 1 | Open error |
| 2 | End of file |
| 8 | File is open for writing |
| 9 | I/O error |

Files are opened on the first call for a particular name and closed when the
script terminates. They remain open between function calls.

#### `write(filename, record[, append])`

Writes a record to `filename`. The first call opens the file for writing and
destroys an existing file. If `append` is supplied, records are appended
instead.

| Code | Meaning |
| ---: | --- |
| 0 | Success |
| 1 | Open error |
| 8 | File is open for reading |

#### `close(name)`

Closes a named file. Close a file before reading data that was written to it;
`close` can also be used to rewind a file.

| Code | Meaning |
| ---: | --- |
| 0 | Success |
| 1 | File is not open |

#### `sys(command)`

Added in version 2.1.1.b0, `sys` submits `command` to `/bin/sh` and returns
the text written to standard output. The shell return code is not captured, so
an empty result may mean either no output or a failed command. Standard error
appears in the console unless the command redirects it.

```text
cmd1 = "ls ./foo"
cmd2 = "ls ./foo 2>&1"
cmd3 = 'echo Hello, world!'
res1 = sys(cmd1); say 'cmd1 returned ->'res1'<-'
res2 = sys(cmd2); say 'cmd2 returned ->'res2'<-'
res3 = sys(cmd3); say 'cmd3 returned ->'res3'<-'
```

For a missing `./foo`, a session might look like this:

```text
ga-> test_sys
ls: ./foo: No such file or directory
cmd1 returned -><-
cmd2 returned ->ls: ./foo: No such file or directory<-
cmd3 returned ->Hello, world!<-
ga->
```

(commands)=
## Commands that complement the scripting language

Several GrADS commands are especially useful in scripts, even though they are
not exclusively scripting commands.

### `query <option>` or `q <option>`

With no option, [`query`](gradcomdquery.md) lists the available options. Useful
script-oriented options include:

| Command | Result |
| --- | --- |
| `q define` | Lists all defined variables |
| `q define varname` | Shows dimensions, coordinate axes, calendar type, and climatological status |
| `q defval ival jval` | Returns the defined-grid value at `(ival, jval)` |
| `q dims` | Shows the current dimension environment |
| `q file n` | Shows information about open file `n` |
| `q files` | Lists open files |
| `q fwrite` | Shows the file used by `fwrite` |
| `q gxinfo` | Shows graphics settings and plot limits |
| `q pos` | Waits for a mouse click and returns its position |
| `q shades` | Shows shaded-contour colors and levels |
| `q time` | Shows the current file time range |
| `q transform coord1 coord2` | Converts between screen, world, and grid coordinates |

To modify values in a `defined` variable, combine `q defval` with
[`set defval`](gradcomdsetdefval.md). This example queries `sst` at grid point
`(i,j)` and replaces values below `-1.6` with `bad_value`:

```text
'q defval sst 'i' 'j
val = subwrd(result, 3)
if (val < -1.6)
  'set defval sst 'i' 'j' 'bad_value
endif
```

The output from `q gxinfo` may look like:

```text
Last Graphic = Line
Page Size = 11 by 8.5
X Limits = 2 to 10.5
Y Limits = 0.75 to 7.75
Xaxis = Lon Yaxis = Val
Mproj = 2
```

The projection codes are:

| Code | Projection |
| ---: | --- |
| 1 | Scaled (no preservation of aspect ratio) |
| 2 | Lat/lon (2-D horizontal fields) |
| 3 | Northern polar stereographic |
| 4 | Southern polar stereographic |
| 5 | Robinson (longitude -180 to 180 and latitude -90 to 90) |

The transform form is `q transform coord1 coord2`, where `transform` is one of:

| Transform | Conversion |
| --- | --- |
| `xy2w` | Page (XY) coordinates to world coordinates |
| `xy2gr` | Page (XY) coordinates to grid coordinates |
| `w2xy` | World coordinates to page (XY) coordinates |
| `w2gr` | World coordinates to grid coordinates |
| `gr2w` | Grid coordinates to world coordinates |
| `gr2xy` | Grid coordinates to page (XY) coordinates |

XY coordinates are inches on the 11-by-8.5 or 8.5-by-11-inch virtual page.
World coordinates are latitude, longitude, level, time, or value, depending on
the dimension environment and the displayed grid. Time uses GrADS absolute
date/time format. Grid coordinates are the `i,j` indices of the displayed
grid. For station data, grid and world coordinates are equivalent except for
time. Wrapped global grids can produce grid numbers outside the physical file
range; the conversions remain consistent, but scripts should account for this.

Coordinate transforms are valid only after a display and apply to the most
recent displayed item.

(scriptfindstn)=
### `set gxout findstn`

With [`set gxout findstn`](gradcomdsetgxout.md), `display` takes three
arguments: a station expression followed by the X and Y screen coordinates to
search. GrADS reports the station ID, longitude, and latitude nearest that
position. X and Y must be the varying dimensions, and a regular graphical
display must have been issued first.

### `set dbuff on|off`

[`set dbuff`](gradcomdsetdbuff.md) controls double buffering for scripted
animation. [`clear`](gradcomdclear.md) also turns double buffering off.

### [`swap`](gradcomdswap.md)

`swap` exchanges the front and back buffers when double buffering is on. It
has no effect when double buffering is off. A typical loop is:

```text
set dbuff on
* start looping
  display something
  swap
* end loop
set dbuff off
```

(widgets)=
## Widgets

GrADS can implement a graphical user interface with buttons and pull-down
menus. These widgets provide a point-and-click interface between a GrADS user
and a script. The Cairo display interface in version 2.1 and later does not
support widgets.

### Buttons

This example defines colors, creates a button, and draws it:

```text
set rgb 90 100 100 100
set rgb 91  50  50  50
set rgb 92 200 200 200
set button 2 90 91 92 3 90 92 91 6
draw button 1 5.5 1 2 0.5 This is a Button
```

See [`set button`](gradcomdsetbutton.md) and
[`draw button`](gradcomddrawbutton.md) for the button properties and position.
A button starts `ON`. After a click requested by [`q pos`](gradcomdqpos.md),
its state changes from `1` (on) to `0` (off), and a later click changes it back.
[`redraw button`](gradcomdredrawbutton.md) can change the state programmatically.

After a click, `q pos` returns:

```text
Position = xpos ypos mousebutton widgetclass buttonnumber buttonstate
```

| Field | Meaning |
| --- | --- |
| `xpos`, `ypos` | Click position in virtual-page units |
| `mousebutton` | `1`, `2`, or `3` for left, center, or right button |
| `widgetclass` | `1` for a button |
| `buttonnumber` | Number assigned when the button was drawn |
| `buttonstate` | `0` (off) or `1` (on) |

If no button was clicked, `widgetclass` is `0` and the button fields are
absent.

### Drop menus

Drop menus provide the same point-and-click interaction. See
[`set dropmenu`](gradcomdsetdropmenu.md) and
[`draw dropmenu`](gradcomddrawdropmenu.md) for their properties.

After a menu click, [`q pos`](gradcomdqpos.md) returns:

```text
Position = xpos ypos mousebutton widgetclass menunumber inum
```

| Field | Meaning |
| --- | --- |
| `xpos`, `ypos` | Click position in the menu base, in virtual-page units |
| `mousebutton` | `1`, `2`, or `3` for left, center, or right button |
| `widgetclass` | `3` for a drop menu |
| `menunumber` | Number assigned when the menu was drawn |
| `inum` | Selected item number |

When no item is selected, both `menunumber` and `inum` are `-1`.

The following script updates a menu after the user makes a selection:

```text
'reset events'
'set rgb 90 100 100 100'
'set rgb 91 150 150 150'
'set rgb 92 200 200 200'
'set dropmenu 1 91 90 92 0 91 90 92 1 91 90 92 90 92 6'
'draw dropmenu 1 1 8 1.5 0.5 Select a Variable | Wind | Temperature | Height | SLP '
noselect = 1
while (noselect)
  'q pos'
  menunum = subwrd(result, 7)
  menuitem = subwrd(result, 8)
  if (menunum = 1)
    if (menuitem = 1) ; newbase = 'Variable = Wind' ; endif
    if (menuitem = 2) ; newbase = 'Variable = Temp' ; endif
    if (menuitem = 3) ; newbase = 'Variable = Height' ; endif
    if (menuitem = 4) ; newbase = 'Variable = SLP' ; endif
    'draw dropmenu 1 1 8 1.5 0.5 'newbase' | Wind | Temperature | Height | SLP '
    noselect = 0
  endif
endwhile
```

Cascading menus use a `>number>` item to identify the next menu:

```text
'clear'
'set rgb 90 100 100 100'
'set rgb 91 150 150 150'
'set rgb 92 200 200 200'
'set button 1 91 -1 -1 1 91 90 92 12'
'draw button 1 1 8 1 0.5 quit'
'set dropmenu 1 91 -1 -1 1 91 90 92 1 91 90 92 90 92 6'
'draw dropmenu 1 1.5 7.5 2 0.5 Menu Base | Space | Earth >05> | Sun | Moon'
'draw dropmenu 5 cascade Ocean | Land | Atmosphere >11> | Biosphere'
'draw dropmenu 11 cascade Snow | Rain | Mist | Tornado '
while (1)
  'q pos'
  say result
  ev = subwrd(result, 6)
  if (ev != 3); break; endif
endwhile
```

Run the demo and inspect the `q pos` output for each menu and cascade item.

### Rubber banding

The `rband` widget lets a user draw a box or line. Configure it with
[`set rband`](gradcomdsetrband.md):

```text
set rband num mode x1 y1 x2 y2
```

| Argument | Meaning |
| --- | --- |
| `num` | Widget number |
| `mode` | `box` or `line` |
| `x1`, `y1` | Lower-left active-area coordinate, in virtual-page units |
| `x2`, `y2` | Upper-right active-area coordinate, in virtual-page units |

In `box` mode, the initial click and release point form opposite corners. In
`line` mode, they form the endpoints of a line.

First obtain the plot limits with [`q gxinfo`](gradcomdquery.md):

```text
Last Graphic = Line
Page Size = 11 by 8.5
X Limits = 2 to 10.5
Y Limits = 0.75 to 7.75
Xaxis = Lon  Yaxis = Val
Mproj = 2
```

Then parse the limits and activate a box over the plot region:

```text
xlims = sublin(result, 3)
ylims = sublin(result, 4)
x1 = subwrd(xlims, 4)
x2 = subwrd(xlims, 6)
y1 = subwrd(ylims, 4)
y2 = subwrd(ylims, 6)
'set rband 21 box 'x1' 'y1' 'x2' 'y2
```

Finally, [`q pos`](gradcomdqpos.md) waits for the click-drag-release event and
returns:

```text
Position = xpos1 ypos1 mousebutton widgetclass widgetnumber xpos2 ypos2
```

| Field | Meaning |
| --- | --- |
| `xpos1`, `ypos1` | Initial click in virtual-page units |
| `mousebutton` | `1`, `2`, or `3` for left, center, or right button |
| `widgetclass` | `2` for an rband |
| `widgetnumber` | Number assigned when the rband was configured |
| `xpos2`, `ypos2` | Release point in virtual-page units |

The two page coordinates can be drawn directly or converted to latitude and
longitude with the `q xy2w` coordinate transform.
